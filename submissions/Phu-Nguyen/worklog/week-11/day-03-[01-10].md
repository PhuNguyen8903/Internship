## 📃 Kiến thức học được
###  week-11 : Use Cases
* Submit ride completion
- REST API cho các trường hợp này nhưng chi phí cao, tự cấu hình
- sử dụng messaging giúp các services đơn giản hơn nhiều, hỗ trợ fanout
- để đảm bảo customer service và các service phía sau được xử lý theo cap thì dùng topic-queue-chaining
* Prebook compaigns
- all at one
- internal decoupling
- có thể kết nối api gateway qua queue thẳng từ api
* Scalability
- Amazon SNS : scale gần như ko giới hạn, mở rộng tùy theo số lượng messages
- FIFO : 300 messages mỗi s
- EventBridge : 10000 events mỗi s
- SQS : tương tự SNS , FIFO 6000 connections mỗi s
- kinesis data streams : scale theo chiều ngang, 1000 operation 1s
- MQ : sử dụng cluster phụ thuộc vào instance types
- Kafka : tương tự MQ , có một serverless mode
* Durability
- cách thức lưu trữ và xử lý data với các dịch vụ
- với các dịch vụ serverless : AWS đảm bảo dịch vụ được hoạt động trên 3 AZ
* persistence
- dữ liệu được lưu trữ trong bao lâu
- SNS và EventBridge ko lưu trữ
- SQS lưu trữ tối đa 14 ngày
- Kinesis data stream : mặc định 24h tùy theo cấu hình để tăng 365days
- MQ : dựa trên instance cho message queue tùy vào lượng lưu trư cho phép của một instance
- kafka : dựa trên instance
* consumption
- SNS : push-based
- SQS : pull-based
- kinesis data stream : pull-based , phía consumer cần tự maintain
- MQ tùy vào cơ chế 
* Retries và failure handling
* pricing

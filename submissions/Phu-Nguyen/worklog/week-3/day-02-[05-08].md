## 📃 Kiến thức học được

###  week-4 bài 1,2,3
* kubernetes giúp quản lý và vận hành một hệ thống chạy container rất rộng
 - Amazon EKS là một dịch vụ chạy kubernetes 
 - giúp giảm thiểu tác vụ liên quan tới opperation và quản trị

* high-level architecture
 - customer VPC : self mangage node groups,managed node groups,private kubernetes APIips,fargate pod ips
 - AWS cloud : được quản lý toàn bộ bởi AWS , fargate  microVM
 - fargate  microVM cung cấp một pod ips cho customer vpc 
 - control plane quản lý data plane thông qua kết nối với private kubernetes API ips nằm trong data plane
 - control plane được chạy song song nhiều AZ , 99.95% SLA , automatic resizing
 * ESK dataplane hay worker node chạy các ứng dụng đóng gói thành container
 - 1 deploy lên dịch vụ hạ tầng EC2 
 - 2 Serverless hay aws fargate 
* truy cập EKS cluster endpoint
 - sau khi tạo cluster sẽ được cấp 1 api ips cho cluster đó và có thể access trực tiếp qua đường public dns này
 - mode 2 mis giữa public và private có thể access thông qua public ip tuy nhiên các trao đổi traffic giữa data plane và control plane được thực hiện private
 - mode 3 yêu cầu cao về security là private 100%

* CNI (container Network interface plugin) : là những container chạy trong pluster chạy tác vụ quản lý ip address của tất cả container trong pluster
* EC2 sẽ cho biết số lượng maximun pods có thể chạy trong 1 instance phụ thuộc vào số lượng card mạng tối đa và địa chị ip address tối đa có thể cấp phép trong card mạng đấy
* max pods = (number of network interfaces x [number of ipaddress per network interface - 1 ] + 2)
* VPC prefix delegation : cấp phát prefix range ip cho một EC2 ENI giúp tăng số lượng dc ip có thể có
* security groups giúp quản lý vấn đề kết nối dịch vụ 
* security groups for Pods : giúp control access cho các dịch vụ an toàn hơn
* Customer networking : giúp mở rộng range ip cấp phát cho pods lớn hơn

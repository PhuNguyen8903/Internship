## 📃 Kiến thức học được
###  week-10 : Serverless
- công nghệ serverless mang lại nhiều lợi thế
- scale dễ dàng 
- là Không cần thiết lập phần cứng
- tự động scale theo nhu cầu theo kiến trúc microservice
- trả chi phí theo requests 
- đảm bảo tiêu chuẩn highly available và secure
* Serverless is more than compute
- có thể triển khai nhiều dạng ứng dụng khác nhau
* How Lambda Work
* High-level view 
- đơn giản là question code có thể viết bằng ngôn ngữ tự chọn
- dùng để call vào service của aws hoặc kết nối vào DB
* customer view
- chỉ là code container
- deploy lambda = config alias cho môi trường khác nhau
- cần có even source mapping cho lambda
- về function : config IAM và permission gọi đến lambda , IAM Execution Role
* AWS lambda under the hood
- mỗi function được tạo deploy trong một sandbox trong microVM
- có 3 thực thi lambda : Event source mapping, Sync,Async
* 3 cách gọi lambda
- Synchronous : request, response , đồng bộ , cần kết quả trả về ngay
- Asynchronous : bất đồng bộ , gọi mà ko chờ kết quả ,thông qua internal queue 
- Event source Mapping : lambda được map vào event source , cho phép xử lý theo batch, cơ chế tương tự bất đồng bộ , khi muốn tiếp kiệm chi phí
* môi trường thực thi của lambda
- môi trường riêng biệt trong sandbox
- aws maintain toàn bộ 
* life cycle của lambda
- chia 2 giai đoạn : cold start,warm start
- Cold start : khởi tạo môi trường,download code, khởi tạo run time, cấu hình library và chạy đoạn code pro-handler
- warm start : chạy handler code
* thực thi lambda song song
- khi thực thi lambda chỉ thực thi 1 event
- nếu có môi trường t2 sẽ khởi tạo môi trường và thực thi event đó 
- khi một môi trường đã thực thi xong mà có thêm một môi trường khác thì môi trường kia sẽ được reuse
* Concurrency
- provisioned concurrency : có thể config số lượng concurrency muốn khít lại
- reserve concurrency : ngược lại với cái trên, dùng để giới hạn traffic nhằm bảo vệ hạ tầng phía sau
